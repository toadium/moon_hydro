## 一、项目概述

**一句话定位**：自研技术研发团队为市县水文部门、山洪预警中心、水利科研院校、数字孪生流域项目，解决基于MoonBit全栈多后端架构的分布式新安江模型+浅水方程水动力耦合流域洪水智能预报问题。

**项目背景**：我国山洪灾害预警、中小流域洪水预报、水库调度核心技术体系以三水源新安江XAJ模型完成流域产汇流演算，配合二维浅水方程（SWE）水动力模型完成河道洪水演进计算。当前主流方案存在三类痛点：Fortran传统代码缺乏现代类型约束、多流域并行易内存越界、难搭建现代Web平台；Python水文建模性能瓶颈严重、不适合实时预报规模化部署；MATLAB商用水文工具闭源收费、私有化部署受限、无法二次开发。传统"后端Rust/Python + 前端Vue/React"前后端分离架构存在数据模型不同步、接口字段错位、序列化错误频发等顽疾，且需维护多套异构代码才能适配服务器、浏览器、嵌入式等多类运行环境。

本项目以新一代编译型语言MoonBit为底座，参考Rust crates.io发布的hydro-suite套件（hydro-core / hydro-xinajiang / hydro-calib）接口规范与算法逻辑，结合Python开源实现OuyangWenyu/hydromodel作为数值比对基准，完成新安江模型与浅水方程双向耦合的MoonBit原生实现；依托Proton+Rabbita官方全栈框架，实现单语言全栈开发、前后端共享统一数据模型，并支持四后端编译打包，一套源码覆盖全部部署场景。

## 二、项目名称与品牌故事

**项目名称**：沐澜水文（moon-hydro）

**命名理由**："沐"本义为沐浴、浸润，象征水文仿真对流域水文的深度浸润与精细推演；"澜"本义为大波浪，直指洪水演进与水动力耦合核心场景；"水文"明示应用领域。四字组合既点明技术定位，又锚定应用场景，简练专业，便于面向水利行业用户传播。

**品牌故事摘要**：沐澜水文诞生于一个朴素愿景——让每一个流域都能拥有一套算得快、算得准、跑得动的洪水预报系统。我们以MoonBit语言为笔，将经数十年验证的新安江模型与浅水方程耦合机理重新书写，让一套源码同时运行于服务器集群、浏览器、云函数与嵌入式预警终端。推演流域，智护安澜——这是沐澜水文对每一位水文工作者的承诺。详细品牌叙事见 `03-品牌故事.md`。

3. 难以一套源码同时适配服务器、Wasm云函数、浏览器、嵌入式四类运行环境；
4. 模型扩展能力受限，耦合水动力方程、接入AI时序预测、对接GIS平台改造门槛高。

### 4.1 核心功能清单

| 序号 | 功能名 | 一句话说明 |

| 2 | 浅水方程SWE求解器 | 基于有限体积法开发二维浅水方程离散求解器，支持地形底坡、河道糙率、边界条件配置 |
| 3 | 模型双向耦合 | 新安江产流量作为河道侧向通量，河道水位反馈调整地下径流储量，实现两套模型双向联动 |

| 5 | 精度评价体系 | NSE、KGE、PBIAS水文精度评价，国标GB/T 22482洪水预报等级自动判定 |
| 6 | Proton后端API服务 | 标准化RESTful接口（仿真、率定、评价、批量任务），支持多方案集合预报 |

| 10 | 四后端编译支持 | wasm-gc、wasm-wasi-gcc、native、JS一套源码四类产物打包部署 |
| 11 | SQLite数据持久化 | 流域信息、气象时序、仿真方案、历史结果数据库存储 |

### 4.2 产品亮点

1. **单语言全栈**：前后端共享唯一一套数据模型，从底层根除接口错位、序列化异常顽疾；
2. **一套源码四后端**：wasm-gc、wasm-wasi-gcc、native、JS四类产物一键编译，覆盖全部署场景；
3. **机理+AI混合预报预留**：统一HydroModel Trait接口，预留LSTM、PINN等AI水文模块扩展；
4. **工业级精度**：与原版Rust代码相对误差＜0.1%，完全兼容现行水文参数体系；
5. **高性能**：同等网格条件下仿真效率为Python版本15~40倍，性能趋近原生Rust。

## 五、技术方案

### 5.1 技术栈选型及理由

| 类别 | 选型 | 选型理由 |
|------|------|----------|
| 核心语言 | MoonBit | 静态强类型、Trait泛型、Wasm/Native多后端统一编译，适配高性能科学计算与全栈Web开发 |
| 后端框架 | Proton | MoonBit官方高性能Native后端框架，原生支持序列化绑定、跨目标编译 |
| 前端框架 | Rabbita | MoonBit官方TEA架构纯函数式前端框架，与后端共享模型 |
| 数值计算 | moonNum | 对标Rust ndarray的多维数组、线性代数、SIMD加速库 |
| 数据库 | sqlite3 | 轻量级嵌入式数据库，适配native与wasm-wasi-gcc后端 |
| 序列化 | serde | MoonBit官方JSON序列化库，四大后端行为统一 |
| 异步运行时 | async | MoonBit官方异步调度运行时，支撑并行仿真任务 |
| 前端UI | Rui | MoonBit生态图表与界面组件库 |
| 移植参考来源 | hydro-suite套件（crates.io）+ OuyangWenyu/hydromodel（Python） | Rust发布包hydro-core/hydro-xinajiang/hydro-calib提供接口规范与算法逻辑；Python开源实现提供新安江三水源数值比对基准 |

### 5.2 系统架构简述

采用MoonBit Workspace多目标一体化工程，划分shared共享模型层、backend后端层、frontend前端层。shared层定义唯一一套水文数据结构与算法内核，四后端完全复用；backend层基于Proton搭建RESTful API与异步任务调度；frontend层基于Rabbita+Rui搭建TEA架构可视化平台。整体分层：驱动层 → 概念性水文层（新安江） → 耦合接口层 → 水动力演进层（SWE） → 评价与率定层 → 应用服务层。

### 5.3 关键技术难点与对策

| 难点 | 对策 |
|------|------|
| Rust ndarray → moonNum数组运算无缝替换 | 广播运算、循环迭代、矩阵运算逐模块改写，核心公式逻辑保持不变 |
| 新安江与SWE双向耦合稳定性 | 分步耦合：先稳态单向验证，再动态双向反馈；预留耦合系数松弛调整参数 |
| 四后端跨平台浮点一致性 | 单元测试覆盖全部四类目标，每次迭代自动执行四目标全量测试 |
| 大规模多流域并行性能 | 参考hydro-suite成熟并行迭代思路，moonNum原生支持分片并行遍历 |
