# 审查范围界定

## 审查目标

全面审查 moon_hydro 项目所有模块的源代码，确保代码质量、正确性、设计合理性和可维护性。

## 审查依据

- MoonBit 语言特性与惯用写法
- 项目现有代码的设计模式和风格作为审查基线
- 水文预报领域知识（新安江模型、浅水方程、SCE-UA 率定等）

## 审查重点

| 维度 | 关注点 |
|------|--------|
| 正确性 | 逻辑错误、边界条件、异常路径、类型使用、错误处理 |
| 设计合理性 | 职责划分、抽象层次、依赖关系、可测试性 |
| MoonBit 特性 | Option/Result 使用、标准库利用、惯用写法 |
| 可读性/可维护性 | 命名、结构、控制流、必要注释 |
| 性能 | 不必要拷贝、低效算法、资源管理 |
| 安全性 | 注入、越权、敏感数据处理（auth/persistence 模块重点） |

## 审查范围

全量审查所有 8 个模块的全部源码文件（含测试代码）：

| 模块 | 文件数 | 说明 |
|------|--------|------|
| shared/ | 28 | 核心层：数据模型+算法内核（新安江/SWE/耦合/率定/评价/时间序列/批量/任务调度/权限等） |
| ml/ | 8 | AI 机器学习层：矩阵/LSTM/混合预报 |
| gis/ | 8 | GIS 接口层：DEM 分析/河网提取/流域分析 |
| flood/ | 6 | 洪水淹没推演层：淹没仿真/风险图/损失评估 |
| persistence/ | 4 | 持久化存储层：DataStore/C FFI 文件 I/O |
| backend/ | 3 | 后端 CLI：入口分发/20 个子命令 |
| frontend/ | 7 | 前端 TEA 架构：Model/Msg/Update/View |
| 总计 | 64 | 约 16,936 行 |

## 排除范围

- `_build/` 构建产物
- `.git/` 版本控制
- 文档文件（*.md）
- C 文件（fileio.c，仅作为 FFI 参考）

## 背景

moon_hydro 是基于 MoonBit 的分布式新安江模型+浅水方程水动力耦合流域洪水智能预报系统，版本 v0.9.0。项目已有多次代码审查修复记录，本次为新一轮全面审查。
